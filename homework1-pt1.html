From Private Key to Public Key

A toy elliptic-curve demo: Q = k·G on y² = x³ + 7 (mod 17). Ethereum uses the same kind of curve (secp256k1), with a 256-bit p.

1. Private key → public key
Hop k times from the base point G on the curve: the landing point is Q = k·G.
2. A shortcut for big keys
Double-and-add needs only as many steps as k has bits (about 256 for a real key) instead of k.
3. One-way, not a hash
Q shows some structure, so it is not a scrambler; its security is that finding k from Q is infeasible (ECDLP).

What is this about?

Private key: a secret number k. Whoever knows it can sign transactions, that is, prove the account is theirs.
Public key: a point Q computed from k (Q = k·G). It can be shared: others use it to check signatures, but cannot get k back from it.

Purpose of this exercise: compute Q = k·G on a tiny curve (point addition, then the double-and-add shortcut), watch it step by step, and test statistically whether the results look random. The goal is to see why this is a one-way function and how it differs from a hash function.

Show the formulas (all arithmetic is mod p)

Addition P ≠ Q: λ = (y₂ − y₁)/(x₂ − x₁), x₃ = λ² − x₁ − x₂, y₃ = λ(x₁ − x₃) − y₁
Doubling P + P: λ = 3x₁²/(2y₁), x₃ = λ² − 2x₁, y₃ = λ(x₁ − x₃) − y₁
λ is the slope of the line through the two points (the tangent when doubling). "Dividing" mod p means multiplying by the modular inverse.

Show the rule

Write k in binary and read the bits from left to right. Start from ∞. For every bit: double the current point; if the bit is 1, also add G. Doubling and adding use the formulas above. The number of steps is the number of bits of k (about 256 for a real key) instead of k.

5Conclusion in simple words

Two different jobs. A hash is like a blender: whatever goes in, what comes out looks random and you cannot tell what went in. Its goal is to scramble, which is why we tested bit balance, evenness, repeated values and avalanche. The curve operation Q = k·G is like a padlock: easy to snap shut (compute Q from k), very hard to open (find k from Q). A padlock does not have to look random; it only has to be hard to open.

What the tests showed. Part of the results look random (the bits are close to 50%, the avalanche is close to 50%), and part show structure (the x values come in pairs, and neighbouring keys are linked by the exact rule (k+1)G = kG + G). That is fine: a visible structure does not make it easy to find k.

What really protects it. With p = 17 or with the larger curve you can try every possible k in a blink. With the 256-bit numbers of Ethereum there are about 2²⁵⁶ possibilities, which is impossible to try. That is the security of the one-way function.

Why Ethereum uses both. The curve turns the private key into a public key; a hash then turns the public key into the short address.
