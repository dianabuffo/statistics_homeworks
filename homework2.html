1 Toy ECC scheme on secp256k1

Connection to Homework 1 pt.1. In Homework 1 pt.1, we studied scalar point multiplication Q = k·G on a toy curve. Here, we extend this primitive into a full hybrid encryption protocol (ECIES / ElGamal-style) on the production secp256k1 curve (y² = x³ + 7 mod p with 256-bit prime p).

Bob publishes public key Q = k·G. When Alice sends a message, she samples a fresh ephemeral scalar r, computes public ephemeral point C1 = r·G, and shared point S = r·Q = r·(k·G) = k·(r·G) = k·C1. The x-coordinate of S is hashed with SHA-256 to produce an unpredictable keystream, and the plaintext message is combined via XOR (C2 = M ⊕ keystream). Bob decrypts by recovering S using his secret k.

2 The Caesar cipher

Classical Monoalphabetic Substitution. The Caesar cipher shifts every alphabet character by a constant offset s ∈ {0, …, 25} modulo 26:
Encryption: Ci = (Pi + s) mod 26  |  Decryption: Pi = (Ci − s) mod 26
Non-alphabetical characters (spaces, punctuation) are preserved in the clear.

Core Mathematical Divergence:
  • Caesar: Uses a constant shift scalar across the entire text stream. Because Ci = Pi + s, any language property Pi = Pj guarantees Ci = Cj. The probability distribution of the ciphertext is an exact rigid rotation of the language histogram.
  • Toy ECC: Employs an elliptic curve one-way trapdoor to securely agree on a 256-bit point, from which a cryptographically strong pseudo-random keystream is derived using SHA-256. Each byte position receives an uncorrelated, unpredictable mask byte, which destroys character-frequency signatures, n-grams, and word boundaries.

4 Statistical cryptanalysis of the Caesar cipher

Theoretical Foundation: Language Redundancy & Unicity Distance. Natural languages are heavily redundant (English redundancy ≈ 75%). In a monoalphabetic substitution cipher, this redundancy survives entirely in the ciphertext. Shannon established that the unicity distance (the minimum ciphertext length needed to identify the encryption key uniquely) for a cipher with key space |K| = 26 is:
U ≈ H(K) / D ≈ log2(26) / (RL · log2(26)) ≈ 4.70 / (0.75 × 4.70) ≈ 1.33 words (≈ 20–30 characters)
Below this threshold, multiple keys produce plausible-looking English fragments. Above this threshold, statistical tests single out the true key with overwhelming probability.

Comparison of Cryptanalytic Decision Rules:
Rule / Method Algorithmic Mechanism Strengths & Vulnerabilities
1. Most Frequent Letter Identifies the peak ciphertext frequency symbol and aligns it with language peak 'E' (s = (peak - 4) mod 26). Extremely fast, but fragile on short texts where 'T', 'A', or 'O' can randomly outnumber 'E'.
2. Chi-Square Goodness-of-Fit (χ²) Calculates χ²(s) = ∑ (Oi - Ei)² / Ei over all 26 letter frequencies simultaneously. Robust against small deviations because all 26 letters contribute. Minimum score yields key.
3. Bigram Log-Likelihood (n=2) Scores decryptions by summing ∑ log P(ci, ci+1) of adjacent letter pairs from corpus model. Captures syntactic grammar (e.g. TH, HE, IN, ER). Highest scoring decryption across short windows.
4. Dictionary Word Matching Searches candidate decryptions for top English stop words (THE, AND, OF, TO, IN, IS, THAT, FOR...). Infallible when spaces are present; completely useless if spaces are stripped or corrupted.

Summary of Empirical Limitations:
  • Sample Size Noise: Under 15 letters, statistical variance overwhelms the distribution. Several candidate keys produce indistinguishable χ² values.
  • Threshold of Reliability: Between 30 and 40 letters, bigram scoring and χ² reach >95% accuracy, verifying Shannon's unicity distance theorem.
  • Language Specificity: Attacking an Italian or French ciphertext with an English training profile results in catastrophic key misclassification.

5 Attack on the toy ECC scheme

Algebraic Nature of the Attack. Unlike the statistical attack against Caesar (which requires linguistic redundancy), the attack on the restricted ECC scheme is purely algebraic. The adversary inspects Bob's public key Q and knows that k ∈ [1, 2bits]. For each candidate scalar k', the attacker computes k'·G on secp256k1 and checks for exact point equality with Q.

A match provides 100% mathematical certainty. With k recovered, the attacker computes S = k·C1, derives the SHA-256 keystream, and decrypts C2 immediately.
Algorithmic Comparison: Exhaustive Search vs. BSGS:
Algorithm Time Complexity Space Complexity Operational Principle
Exhaustive Search O(K) point additions O(1) memory Sequentially computes G, 2G, 3G, …, k'G using Jacobian point doublings/additions until matching Q.
Baby-Step Giant-Step (BSGS) O(√K) operations O(√K) memory Computes m = ⌈√K⌉. Precomputes table of baby steps j·G for j ∈ [0, m). Then computes giant steps Q − i·(mG) until finding a collision. Yields k = i·m + j.

Why This Attack Fails Completely on Full-Scale secp256k1:
  • Immense Combinatorial Space: A true secp256k1 private key is a 256-bit scalar chosen uniformly from order n ≈ 1.158 × 1077.
  • Square-Root Infeasibility: The fastest known generic discrete logarithm solvers (Pollard's ρ, BSGS) require √2256 = 2128 ≈ 3.4 × 1038 group operations.
  • Physical Thermodynamics & Energy Limits: By Landauer's principle and Bremermann's computational limit, expending the energy to perform 2128 bit flips would require more power than the total energy output of our Sun over millions of years. Real ECC is secure because of this computational infeasibility.

In-Depth: Alternative Attacks and Root-Cause Vulnerability Analysis

1. Vulnerabilities Arising from the Restricted Key Space

  • Pollard's Kangaroo (Lambda) Method for Bounded Intervals: When the private key is known to lie in a bounded window [a, b] of width W = b - a, Pollard's kangaroo algorithm achieves the same O(√W) time complexity as BSGS, but requires O(1) memory! It deploys a "tame" kangaroo and a "wild" kangaroo hopping pseudo-randomly along curve points until the wild kangaroo falls into the tame kangaroo's trap (collision).
  • Weak Ephemeral Nonce r: If Alice chooses her ephemeral scalar r from a restricted range (e.g. 20 bits) even while Bob's private key k is a full 256-bit number, the entire scheme collapses! The attacker applies BSGS directly to public point C1 = r·G to recover r, and then computes S = r·Q to decrypt the payload, completely bypassing Bob's 256-bit security.

2. Vulnerabilities Arising from the Toy Scheme's Architecture (Even with 256-bit keys)

  • Lack of Message Authentication (Bit-Flipping Malleability): The toy scheme computes C2 = M ⊕ Keystream without a Message Authentication Code (MAC). An attacker in the middle can flip bit j of C2; upon decryption, bit j of the recovered plaintext is flipped with probability 1 ((C2 ⊕ Δ) ⊕ KS = M ⊕ Δ). This violates Chosen-Ciphertext Security (IND-CCA2). Production systems must use Authenticated Encryption (AEAD like AES-GCM or ECIES with HMAC).
  • Ephemeral Scalar Re-use (Two-Time Pad Catastrophe): If Alice reuses the same ephemeral scalar r for two distinct messages M1 and M2, the keystream is identical! The attacker computes C21 ⊕ C22 = M1 ⊕ M2, eliminating the cryptographic key entirely and exposing the plaintexts to statistical crib-dragging.
  • Missing Point Validation (Invalid Curve Attacks): The toy scheme does not verify whether received point C1 satisfies the curve equation y² ≡ x³ + 7 mod p and has order n. An attacker can supply points on weak curve twists with small prime factors, leaking Bob's private scalar modulo small primes via the Pohlig-Hellman algorithm.
  • Plaintext Length Leakage: Because stream ciphers encrypt byte-for-byte, the exact payload length is visible to eavesdroppers (|C2| = |M|).

6 Synthesis and conclusions

This laboratory work demonstrates the fundamental contrast in modern cryptology:

1. Statistical vs. Algebraic Security: The Caesar cipher fails because it leaves the structural fingerprint of the source language completely intact. A small sample of letters is sufficient to recover the secret offset through statistical correlation. The toy ECC scheme successfully conceals all statistical language patterns, producing a byte stream indistinguishable from true randomness.

2. Computational Security: The toy ECC scheme fails in our browser solely because we deliberately artificially restricted the scalar exponent space. In a genuine deployment on secp256k1, the 256-bit scalar order renders square-root and exhaustive attacks physically impossible. However, true production security also demands authenticated encryption (AEAD), proper public point validation, and cryptographically fresh nonces to prevent protocol-level malleability attacks.
